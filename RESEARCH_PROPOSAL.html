What Is This Research About?

When you tell a language model conflicting things — "the color is red," then later "the color is blue" — and ask it to recall, a striking asymmetry emerges:

Retroactive Interference (RI)

"What was the first value?"

~90% accurate

Models easily recall the first value despite later updates

vs

Proactive Interference (PI)

"What was the last value?"

~40-55% accurate

Models struggle to recall the most recent value

The Opposite of Human Memory In human cognition, new memories overwrite old ones (retroactive interference dominates). Transformers show the reverse: old information blocks access to new information (proactive interference dominates). This is PI > RI — and it holds across every model we tested, from 135M to GPT-4 class.

The ACL paper established that this happens. The NeurIPS expansion explains why — down to specific attention heads, specific layers, and a specific circuit defect.

Why Does This Matter?

For AI Safety & Reliability

  • In-context learning failures: When models can't properly access recent information, few-shot prompting becomes unreliable at scale
  • RAG pipeline degradation: Retrieval-augmented generation assumes models can use the latest retrieved context. PI means earlier retrieved passages can block later, more relevant ones
  • Long-context reliability: As context windows grow to 128K+, the inability to access late-position information becomes a critical limitation

For Scientific Understanding

  • Attention mechanism theory: Proves that causal masking creates an inherent primacy bias — this is architectural, not learned
  • Mechanistic interpretability: Demonstrates a complete causal chain from a behavioral phenomenon to specific circuit components
  • Dual-process evidence: Shows that RI resistance and PI resistance are mechanistically independent (different heads, different scaling)

For Practitioners

  • Prompt engineering: Understanding positional bias helps design prompts that place critical information where models can access it
  • Fine-tuning targets: We identify exactly which 0.14% of parameters to tune to fix the asymmetry
  • Architecture design: Points toward what needs to change in attention mechanisms for better recency handling

The Phenomenon: PI > RI

This tab explains the core phenomenon we are investigating — what proactive and retroactive interference are, how we measure them, and what the ACL paper established.

What Are PI and RI?

The Experimental Setup

We present models with a key-value stream where categories get updated multiple times:

Read the following key-value stream. Each key gets updated multiple times.

color: red          ← initial value (v0)
fruit: apple
color: blue         ← intermediate value (v1)
fruit: mango
color: green        ← final value (v2)
fruit: grape

What was the first value of color?    ← RI test (answer: red)
What was the last value of color?     ← PI test (answer: green)

Retroactive Interference (RI)

Question: "What was the first value?"

Challenge: Later values (blue, green) might overwrite the first (red)

Result: Models handle this easily — high accuracy even with many updates

In human terms: Like remembering your first phone number despite having many since

Proactive Interference (PI)

Question: "What was the last value?"

Challenge: Earlier values (red, blue) might block access to the latest (green)

Result: Models struggle badly — accuracy drops quickly with interference

In human terms: Like trying to remember your current password when you've changed it many times

Key Terminology "Proactive" and "retroactive" refer to the direction of interference relative to the target memory. In PI, earlier memories proactively block access to later ones. In RI, later memories retroactively interfere with earlier ones. The finding is that transformers are resistant to RI but vulnerable to PI — the opposite of the human pattern.

All 39 models — from 135M to GPT-4 class, spanning 7 model families — show PI > RI. This is not a quirk of one architecture or training set. Cohen's d = 1.73 is a massive effect size.

Across all 39 models, RI performance and PI performance are uncorrelated (R² = 0.044). This suggests they rely on different mechanisms — the dual-process hypothesis.

The Gap in the ACL Paper The ACL paper proves THAT PI > RI exists and characterizes its behavioral properties. It does NOT explain WHY. That's what the NeurIPS expansion addresses: the mechanistic explanation, from attention heads to circuits to a precise causal chain.

Controls & Methodology Safeguards

Single-Token Values (Critical)

Hard-Won Lesson Multi-token synthetic values (e.g., "Hat380", "Art42") are unusable for mechanistic probing. Values in the same category share the first subtoken, making logit lens and DLA return identical results for initial and final values. All Phase 2 analyses use a pool of 96 common English words verified as single-token in the target tokenizer.

Tokenizer Trap

Values appear in prompts as " red" (space-prefixed), not "red" (bare). These are different token IDs. The logit lens must track both variants: space-prefixed dominates in early-mid layers, bare form takes over at the final layer.

Token Frequency Balance

For each trial, we log the mean log-frequency of initial and final value tokens and report correlation between frequency and accuracy — ensuring results aren't driven by common vs. rare words.

Paired Design

All mechanistic analyses run RI and PI with identical prompts — same categories, same values, same interleaved stream. Only the query word ("first" vs "last") changes. This isolates the effect of instruction processing.

Context Length Safety

Before running any behavioral sweep cell, we tokenize a sample prompt and verify it fits within 90% of the model's maximum context. Cells that overflow are logged as skipped.

Phase 2: Mechanistic Analysis

Core Approach Run each analysis at MULTIPLE operating points (A through E), not just the "sweet spot." The mechanism may change between mild and severe interference. All analyses use paired RI/PI trials with identical prompts except the query word.
Step 2.1: Logit Lens — "What does the model think at each layer?"

What: At each layer, project the residual stream at the answer position through the unembedding matrix to see which token the model would predict if forced to output at that layer.

Why: Shows how the model's "belief" about the answer evolves across layers. If the first value dominates at every layer even in PI trials, the model never forms the correct representation — the problem is early and pervasive.

How:

  • 100 trials per operating point
  • Track P(initial_value) and P(final_value) at each layer
  • Both space-prefixed and bare token variants
  • TransformerLens: cache["resid_post", layer]

Key questions:

  • Does the initial value dominate all layers (as found in SmolLM2)?
  • Is there a layer where the final value appears briefly before being suppressed?
  • Does the pattern change across operating points?

Paper figure: Layer-by-layer probability curves for P(initial) and P(final), with CI bands, separate per operating point.

Step 2.2: Attention Head Classification — "Which heads retrieve values?"

What: Classify every attention head by its function during value retrieval. The most important mechanistic step.

Why: Identifies the specific heads responsible for value retrieval and whether they have primacy bias. If retrieval heads ignore the "first"/"last" instruction, that's the smoking gun.

How (per head, at the answer position):

  1. Use token tracker to classify every position (initial_value, final_value, key, instruction, query)
  2. Extract attention vector at the last token
  3. Sum attention weights by semantic role
  4. Compute: retrieval_score = total attention to any value position; primacy_score = attention_to_initial / (initial + final)
  5. Run for both RI and PI trials with identical prompts

Head classification scheme:

CategoryCriterionMeaning
Retrieval headMean retrieval score > thresholdConsistently attends to value tokens
Primacy-biasedPI primacy > 0.6Attends to initial even when asked for last
Recency-responsivePI primacy < 0.4Correctly shifts to final in PI
Condition-sensitive|RI_primacy - PI_primacy| > thresholdChanges behavior with instruction
GQA Complication Qwen2.5-0.5B has 14 query heads but only 2 KV heads (7:1 ratio). Attention patterns are per-query-head, but value vectors are shared within KV groups. If all 7 query heads in a KV group show primacy bias, that's one shared mechanism, not 7 independent ones.
Step 2.3: Direct Logit Attribution (DLA) — "Who pushes the output?"

What: Decompose the model's output logit into per-component (per-head + per-MLP-layer) contributions, exploiting the residual stream's additive structure.

Why: Attention analysis shows where heads LOOK. DLA shows what they DO to the output. A head that attends to the initial value AND promotes it in the logit is doubly confirmed as a primacy mechanism.

How:

# Per attention head: contribution to logit of token t at answer position
logit_diff[layer, head] = (attn_out[layer, head, -1, :] @ W_U[:, initial_token])
                        - (attn_out[layer, head, -1, :] @ W_U[:, final_token])

# Positive = promotes initial value, Negative = promotes final value
# In RI: positive = helpful.  In PI: positive = HARMFUL (primacy intrusion)

Key questions:

  • Do the highest-DLA heads overlap with retrieval heads from Step 2.2? (Convergent evidence)
  • Do MLPs contribute to primacy bias, or is it purely attention?
  • Does any component flip sign between RI and PI? (Instruction-responsive output)
Step 2.4: Activation Patching — "Causal proof"

What: Swap activations between a "clean" run (no interference, model gets it right trivially) and a "corrupted" run (full interference, model may fail). Measure accuracy recovery.

Why: Patching provides causal evidence, not just correlational. If patching at position X recovers accuracy, then position X contains the critical information.

How:

  1. Attribution patching (fast): Gradient-based approximation across full (layer × position) grid
  2. Targeted patching (precise): Actual activation swap at top-20 positions from attribution
  3. Component-specific: Full residual, attention-only, MLP-only at query position
  4. Layer-specific: Early (0-8), mid (8-15), late (16-23) at query position

Key questions:

  • Can we RESTORE PI accuracy by patching? Where is the critical position?
  • Is the problem at value positions (storage failure) or query position (routing failure)?
  • Which layer range contains the critical corruption?
Step 2.5: Ablation & Forced Attention — "Circuit surgery"

What: Surgically modify identified heads: zero them out (ablation) or force their attention to specific positions.

Why: The definitive test. If ablating primacy-biased heads closes the PI-RI gap, they are causal. If forcing them to the correct position gives 100% accuracy, the OV circuit works and the problem is purely in QK routing.

Experiments:

InterventionWhat It TestsExpected Result
Knockout all primacy-biased headsAre they causal for PI > RI?Gap shrinks dramatically
Knockout all recency-responsive headsAre they necessary for retrieval?Both RI and PI go to 0%
Force primacy heads to correct positionIs the OV circuit functional?100% accuracy on both RI and PI
Force primacy heads to wrong positionNegative controlAccuracy destroyed
Step 2.6-2.8: Deeper Investigations

Positional Gradient Analysis

What: Track P(vi) across all N value positions. Is primacy "first only" or gradual?

Why: Distinguishes exact primacy (sharp cliff at v0) from graded recency (spread across late positions).

PI Mass Distribution

What: Where does the peak probability land in PI failures? Is it the actual last position or somewhere nearby?

Why: If the model retrieves "a late value" rather than "the last value," the mechanism is approximate recency, not failed recency.

Instruction Sensitivity Probe

What: Do primacy-biased heads even read the "first"/"last" query word?

Why: If they put zero attention on the query word, they CAN'T be instruction-sensitive — the routing failure is complete and architectural.

Granular Query-Position Patching

What: Patch attn_out vs mlp_out separately at each layer at the query position.

Why: Disambiguates "query representation failure" (model can't understand "last") from "value routing through query position" (correct values get overwritten by primacy-biased heads writing to the query position).

Finding 1 — Head Classification

Most Retrieval Heads Work Correctly. A Small Minority Is Broken.

Of 336 total attention heads, 65 function as value retrievers. 53 of these (82%) correctly shift attention from initial to final value when the query says "last." But 8 heads (12%) always attend to the first value regardless of instruction.

Ablating the 8 primacy-biased heads reduces the RI-PI accuracy gap from 35% to 5%. Ablating the 53 recency-responsive heads kills both RI and PI entirely (0% accuracy).

Finding 3 — Root Cause

Primacy Heads Never Read the Instruction

All 8 primacy-biased heads put literally zero attention on the query word "first"/"last." They attend to early-position value tokens and instruction prefix tokens, completely ignoring the query. They cannot be instruction-sensitive because they never read the instruction.

Evidence: 20 trials, attention to query word = 0.000 for all 8 heads. Script: 17_instruction_sensitivity.py
Finding 4 — Causal Proof

Forcing Heads to Correct Position → 100% Accuracy on Both RI and PI

The OV circuits of the 8 primacy heads are perfectly functional. They correctly copy any value they attend to. The problem is purely in the QK circuit (where they look), not what they output.

Finding 5 — Patching

PI Failure Is Value-Routing Corruption, Not Storage Failure

Patching at value positions does nothing (0% recovery). Patching the full residual stream at the query position fully restores PI accuracy (100%+ recovery). The values are stored correctly in context; the model can't decode "last" into the right retrieval pattern because primacy-biased heads at L16-18 overwrite the query-position representation with initial-value information.

Evidence: 4+10 trials across two patching experiments. Recovery peaks at layers 21-23. Component-specific patching confirms corruption is cumulative in residual stream, not in any single component. Scripts: 15_activation_patching.py, 22_query_patching_granular.py
Finding 6 — Positional Asymmetry

Primacy Is Exact, Recency Is Approximate

For RI, the model places P=0.78 on v0 with a sharp cliff (v1=0.00). For PI, probability is spread across the last ~25% of positions, peaking at the ~80th percentile — not the actual last position. The model retrieves "a late value," not "the last value."

Evidence: 5+8 trials across two experiments. PI peak drifts further from actual last position as interference increases. Scripts: 13_positional_gradient.py, 14_pi_mass_distribution.py
Finding 7 — Layer Localization

Two-Layer Corruption: L16-18 (Primacy Heads) + L20-23 (Unknown)

Ablating the 8 primacy heads eliminates query-position patching recovery at L16-18 (from 35% → 5%), confirming they cause the corruption there. But L20-23 shows 81-100% recovery regardless of ablation — an independent corruption source exists in late layers.

Adding a recency bias (λ=10) to only value-token positions in the 8 primacy heads brings PI from 70% to 90% while RI stays rock-solid at 90%. The gap goes to zero. Blind positional bias (applied to all tokens) fails because attention shifts to non-value tokens instead.

The Complete Mechanistic Story

This tab synthesizes all findings into the paper-ready narrative: a step-by-step causal explanation of why transformers show PI > RI.

The Causal Chain (8 Steps)
Step 1
Retrieval Architecture
65 out of 336 attention heads function as value retrievers, attending to value token positions from the answer position. The other 271 heads handle instruction processing, key matching, and other functions.
↓
Step 2
The Majority Works Correctly
53/65 retrieval heads (82%) are recency-responsive — they shift attention from initial to final value when the query says "last" instead of "first." These heads correctly process the instruction.
↓
Step 3
A Minority Is Broken
8/65 retrieval heads (12%), led by L16H3, are primacy-biased — they always attend to the first value regardless of instruction. L16H3 has condition sensitivity = 0.008 (effectively zero).
↓
Step 4
WHY They're Broken: Zero Query Attention
These 8 heads put literally zero attention on the query word "first"/"last." Their QK circuits attend to early-position value tokens and instruction prefix tokens. They never read the instruction, so they can't respond to it.
↓
Step 5
The Minority Corrupts the Query Position
At layers 16-18, the primacy-biased heads write initial-value information into the residual stream at the query position. This cumulative corruption drowns out the correct "last" signal by the time the model generates an answer. (Confirmed: ablating these heads reduces L16-18 patching recovery from 35% → 5%.)
↓
Step 6
The OV Circuit Is Fine — QK Is Broken
Forcing the 8 heads to attend to the correct position gives 100% accuracy on BOTH RI and PI. The gap goes to zero. These heads are powerful retrievers when aimed correctly — the problem is purely where they look (QK), not what they output (OV).
↓
Step 7
Primacy Is Exact, Recency Is Approximate
The initial value gets P=0.78 with a sharp cliff (v1=0.00). The final value probability is spread across the last ~25% of positions, peaking at the 80th percentile rather than the actual last position. The model has exact primacy retrieval but only approximate recency retrieval.
↓
Step 8
The Asymmetry Is Architectural
"First" works because attention naturally defaults to the first occurrence — no explicit routing needed (consistent with causal masking's primacy bias). "Last" requires active QK routing that reads the instruction and redirects to the final position — and a minority of heads can't do this. The asymmetry is a consequence of how causal attention inherently prioritizes early positions.

Open Questions & Weaknesses
Critical Gap: How Does the Minority Override the Majority? DLA shows recency heads win the logit-space tug of war (net -12.86 toward final value). Yet PI accuracy is only 55%. All three initial hypotheses (DLA magnitude, OV gain, last-word effect) were rejected. The mechanism by which 8 heads override 53 is not yet explained.

Leading hypothesis: The effect is trial-dependent and nonlinear. On the ~45% of PI trials that FAIL, primacy heads may dominate via information-flow corruption (corrupting the residual stream that downstream recency heads read), not raw logit magnitude.
N=1 Model Problem All mechanistic findings are on Qwen2.5-0.5B only. Cross-model replication on Qwen-1.5B and Gemma-2B is essential for a NeurIPS submission.
Small Trial Counts Core Phase 2 results use 3-30 trials. Ablation results with 20 trials have confidence intervals of ~±20%. Need 100+ trials for statistical reliability.
L20-23 Corruption Source Unknown Patching at L20+ recovers PI accuracy regardless of whether primacy heads are ablated. Something else corrupts the query position in late layers. Candidates: MLP layers, non-retrieval heads, or accumulated small biases from many components.

Core Claims (What the Paper Will Argue)
  1. PI > RI is universal in transformers. All 39 models tested show it (Cohen's d=1.73). It appears even at 135M parameters and persists across model families.
  2. The cause is a small minority of instruction-insensitive retrieval heads. ~12% of retrieval heads always attend to the first value regardless of instruction. They never read the "first"/"last" query word.
  3. The defect is in QK routing, not OV processing. Forcing the broken heads to attend correctly gives 100% accuracy. The information encoding is fine; the address lookup is broken.
  4. The asymmetry is architectural. Causal attention inherently biases toward early positions (primacy). "First" retrieval is the default. "Last" retrieval requires active routing that a subset of heads can't perform.
  5. RI resistance scales with model capacity; PI resistance does not. Because RI uses the default attention bias (scales with head count and d_model), while PI requires all retrieval heads to be instruction-sensitive (bounded by the weakest heads).
  6. The defect is fixable. Fine-tuning only the QK circuits of 8 heads (0.14% of parameters) can close the gap. This validates the mechanistic explanation and points toward targeted architectural fixes.
